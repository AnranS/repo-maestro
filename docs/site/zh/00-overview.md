# 什么是 maestro？

`maestro` 是一个**多项目 Agent 编排器**，专为那些需要端到端独立交付一整个需求的全栈开发者设计——前端、后端、移动端、基础设施可能分散在多个仓库中，而你希望让一个 AI 助手把这件事当成**一件整体的工作**来规划、派分、验证。

它**不是**一个聊天机器人；**不是**一个 CI 系统；它在两者中间：

- 你用自然语言告诉 `maestro` 一个目标。
- 编排 Agent（默认 Cursor，也可选择 Codex）把它拆成一份 `PLAN.yaml` —— 一个由若干任务组成的 DAG，每个任务作用域只指向一个项目。
- 你确认计划之后，`maestro` 用最大并行度跑这个 DAG，日志流式回传到 web 面板，结束后会生成一份报告。
- 一个**共享记忆层**（L1 事实 + L2 决策）会被自动注入到每个子任务的 prompt 里，保证多个 Agent 跨仓库时保持一致认知。

```text
        ┌────────────────────────────────────────────────────────────┐
        │   你: "给 api + web 加上用户名/密码登录"                     │
        └─────────────────────────┬──────────────────────────────────┘
                                  │
                         ┌────────▼─────────┐
                         │  Planner Agent   │  ← selected provider
                         └────────┬─────────┘
                  生成 PLAN.yaml  │  你 review / 编辑
                                  ▼
                ┌─────────────────────────────────┐
                │  maestro DAG 调度器 (Rust + tokio)   │
                └──┬──────────────┬──────────────┬┘
                   │              │              │
              ┌────▼──┐      ┌────▼──┐      ┌────▼──┐
              │ T1    │      │ T2    │      │ T3    │
              │login- │ ───▶ │login- │ ───▶ │verify │
              │ api   │      │ web   │      │       │
              └───────┘      └───────┘      └───────┘
```

## 为什么需要它？

如果你曾经经历过：

- 同时开五个 Cursor 窗口，就为了在多个仓库之间维持脑内的上下文；
- 把同一份 API 契约连续敲三遍给三个 Agent；
- 忘了某个子任务到底卡在哪一步上；

那你就遇到了 `maestro` 想解决的问题。它的目标是把你这位"一人团队"升级成一支**协调的**一人团队。

## 设计支柱

| 支柱 | 落地形式 |
|---|---|
| **声明式计划** | `PLAN.yaml` 是一个可读、可改、可版本控制的 DAG。 |
| **人始终在 loop 里** | 每份计划都要 review；任务可以打上 `requires_approval_after` 作为硬卡点。 |
| **共享上下文** | L1 事实 + L2 决策都是 markdown 文件，按依赖拓扑自动注入到 Agent 的 prompt。 |
| **自动接线** | 发现阶段从清单**和源码 import** 推断项目依赖与契约；消费方自动排在生产方之后，并被喂入生产方真实的契约内容。 |
| **韧性 + 可观测** | 有界重试 + 断路器，放弃时升级给人，自动决策账本在报告/跑完摘要/dashboard 都可见。 |
| **monorepo 与 polyrepo** | 跨独立 git 仓的每仓 worktree 隔离，上下文按各项目子树收口。 |
| **Skills 行动手册** | 复用的工作流以"YAML frontmatter + markdown"的形式存在；可以被自动镜像到 `.cursor/rules/` 和 `.claude/skills/`。 |
| **一个二进制** | Rust + 内嵌的 React UI + 内嵌的文档站。丢进 `$PATH` 就跑。 |
| **Agent 无关** | 第一公民是 Cursor，但 Adapter trait 让接 Claude Code / Codex / shell 几乎都是顺手的事。 |

## maestro 不是什么

- ❌ **替代你的 CI**。本地 DAG 跑出来是为了开发期快速迭代，不是为了上线。
- ❌ **托管产品**。所有东西都在本地：代码、会话、记忆。
- ❌ **prompt 管理器**。Skills 关注的是可复用的工作流，不是 system prompt 的微调。
